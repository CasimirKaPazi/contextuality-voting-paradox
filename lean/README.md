# Formal proofs

Lean 4 files that check statements from the notes and the drafts. They form one Lake project with Mathlib as dependency: run `lake build` in `lean/` (toolchain in `lean/lean-toolchain`). The older files use only core Lean; `ProbLine.lean`, `CircleTournaments.lean`, `LoopsOfRelations.lean`, `ProbabilisticArrow.lean`, `PathPinning.lean`, `ArrowGeneral.lean`, `ArrowBase.lean`, `JointDraws.lean`, `Scenarios.lean`, `Rankings.lean`, `GSScenario.lean`, `JoinLotteries.lean`, `Isotropy.lean`, `SummaryAutomaton.lean`, `GSTopTwo.lean`, `GSCorollary.lean`, `CoreDraw.lean`, `StrategicInformation.lean`, `MemoryWalk.lean`, `TwoPlayer.lean`, `TightCounterexample.lean`, `ThreeOutcomes.lean`, `ApprovalVeto.lean`, `CallGame.lean`, `GlobalFormLottery.lean`, `EqualityCriterion.lean`, `Covers.lean`, `ArrowScenario.lean`, `Couplings.lean`, `GlobalForm.lean`, `GlobalFormSP.lean`, `ConsistencyScenario.lean`, `GlobalFormReal.lean` and `CoversDecomp.lean` use Mathlib. Finite statements are proved by computation (`decide`); the others by ordinary proofs. Every file is a module in Lean's module system: it begins with `module`, imports with `public import`, and puts its content in `@[expose] public section`, so that definitions stay unfoldable in the files that import it, as before.

Each file's header names the statements it checks. This file is the index of what is checked formally; the notes and drafts refer to it rather than tracking each file.

What the files leave to standard topology: that a coherent orientation of the triangles is the same as orientability, and the classification of surfaces, which names the resulting surfaces (torus, Klein bottle, sphere, projective plane). What is not formalised: the count over all 18,138 two-player game forms, whose formal version would also need a proof that the enumeration is complete, and Gibbard's 1978 Corollary 2, which `Lotteries.lean` assumes.

What is still to be formalised, and in which order: `roadmap.md` in this folder.
